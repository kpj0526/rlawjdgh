# Chrome 점프 자동화 (작업 요청 001·002)

여러 계정을 등록해 두면 계정마다 **별도의 Chrome**을 열어
`설정 URL 이동 → 로그인 → 점프 4종(라인업/PR · 실시간 출근부 · 매니저 출근부 · 홍보관) 클릭 → 각 확인 창 '확인' → 결과 기록 → Chrome 닫기`
를 정해진 시각·주기마다 반복하는 Windows용 프로그램입니다.

- 프로그램을 켜기만 해서는 어떤 사이트에도 접속하지 않습니다. **전체 시작** 또는 **지금 실행**을 눌러야 실행합니다.
- 대상 사이트 주소는 화면에서 입력합니다(특정 도메인이 코드에 고정돼 있지 않음).
- 실제 계정 없이 검증할 수 있도록 **로컬 모의 사이트**(`mock_site`)를 함께 제공합니다.

## 0. 내려받아 바로 실행 (배포 ZIP, Python 필요 없음)

| 항목 | 조건 |
| --- | --- |
| OS | Windows 10/11 64비트 |
| Chrome | Google Chrome 설치 필요. 평소 쓰는 Chrome을 그대로 씁니다(브라우저를 따로 받지 않음). 확인 버전: 154 |
| 그 밖 | Python, `.venv`, 인터넷 설치 과정 모두 필요 없음 |

1. `ChromeJumper-<버전>-win64.zip`(약 51MB)을 받아 마우스 오른쪽 버튼 → **압축 풀기**로 원하는 폴더에 풉니다. 풀면 약 136MB입니다.
   - ZIP 안에서 바로 실행하지 마세요. 짧은 경로(예: 바탕화면, `C:\Tools`)를 권장합니다.
2. 풀린 `ChromeJumper` 폴더의 **`ChromeJumper.exe`**를 더블클릭합니다.
   - 서명되지 않은 프로그램이라 "Windows의 PC 보호" 창이 뜰 수 있습니다. **추가 정보 → 실행**을 누릅니다.
   - `_internal` 폴더는 실행에 필요하므로 지우거나 옮기지 마세요.
3. 사용법은 3장과 같습니다. 설정·로그는 프로그램 폴더가 아니라 `%APPDATA%\ChromeJumper`에 저장되므로, 새 버전 ZIP을 풀어 실행하면 기존 설정을 그대로 씁니다.
4. 받은 파일이 맞는지는 함께 전달된 SHA-256 값과 비교합니다(PowerShell: `Get-FileHash .\ChromeJumper-0.2.0-win64.zip`).

ZIP에는 프로그램 파일과 `README.txt`(요약 사용법)만 들어 있습니다. 설정, 비밀번호, 로그, 가상환경, 빌드 캐시, 테스트, 모의 사이트는 넣지 않으며, 빌드 스크립트가 이를 검사해 들어가면 빌드를 실패시킵니다.

### 배포 파일 만들기 (개발자용)

```bat
build.bat
```

| 단계 | 내용 |
| --- | --- |
| 1 | `.venv`가 없으면 `setup.bat` 실행, `requirements-build.txt`(PyInstaller 6.22.3 고정) 설치 |

| 파일 | 대상 |
| --- | --- |
| `ChromeJumper-<버전>-win64.zip` | 사용자 배포본 |
| `ChromeJumper-MockSite-<버전>-win64.zip` | QA·점검용 모의 사이트. 사용자에게는 필요 없음 |
| `SHA256SUMS.txt`, `BUILD_INFO.json` | 해시, 크기, 빌드 원본 커밋 |

### 배포 파일 점검 (QA·개발자용)

`ChromeJumper.exe --selftest`는 창 없이 지정 계정들을 '즉시 시작'으로 전체 시작해 1주기씩 실행합니다. 결과를 JSON으로 저장하고, 모두 성공이면 종료 코드 0, 하나라도 실패면 1, 인자 오류면 2를 돌려줍니다. 사용자 설정 폴더는 건드리지 않고, 결과에 비밀번호를 쓰지 않습니다.

```bat
MockSite.exe --port 8765
ChromeJumper.exe --selftest --url http://127.0.0.1:8765/owner --account A:test1:pass1 --account B:test2:pass2 --out result.json
```

## 2. 설치·실행 (소스에서 실행할 때)

탐색기에서 이 폴더를 열고 다음 파일을 더블클릭합니다.

1. `setup.bat` — 처음 한 번만 실행합니다. `.venv` 가상환경을 만들고 Playwright를 설치합니다(인터넷 필요).
2. `run.bat` — 프로그램 창을 엽니다.

명령줄에서 실행할 수도 있습니다.

```bat
setup.bat
.venv\Scripts\python -m chrome_jumper
```

설정과 로그는 `%APPDATA%\ChromeJumper\` 아래에 저장합니다. 환경변수 `CHROME_JUMPER_DATA`로 저장 위치를 바꿀 수 있습니다.

| 파일 | 내용 |
| --- | --- |
| `config.json` | URL, 계정, 옵션. 비밀번호는 암호화된 값만 저장 |
| `logs\chrome_jumper.log` | 실행 로그. 2MB 단위로 최대 5개 보관 |

## 3. 화면 사용법

1. **대상 URL**에 로그인 화면 또는 업소 정보 화면 주소를 넣고 `URL 적용`을 누릅니다. 예: `https://사이트주소/owner`
   - `http://` 또는 `https://`로 시작하는 전체 주소만 받습니다.
   - 바꾼 URL은 다음 실행부터 적용됩니다.
2. `계정 추가`로 계정을 등록합니다. 수정은 `수정` 또는 더블클릭, 삭제는 `삭제`입니다.

   | 항목 | 설명 |
   | --- | --- |
   | 식별 이름 | 화면과 로그에 표시할 이름 |
   | 로그인 ID / 비밀번호 | 비밀번호는 ●로 가려 입력합니다. 수정할 때 비워 두면 기존 비밀번호를 유지합니다 |
   | 활성 | 끄면 전체 시작 때 예약하지 않습니다 |
   | 첫 실행 | **즉시 시작** 또는 **지정 시각에 시작** |
   | 시작 시각 | HH:MM 형식 |
   | 반복 주기(분) | 1~10080(7일) 사이의 숫자. `inf`, `nan`, `1e20`, 0 이하 등은 저장하지 않고 오류를 표시합니다 |
   | 종료 시각 | 선택 항목입니다. 규칙은 4장을 보세요 |
3. `▶ 전체 시작`을 누르면 활성 계정 전부의 예약이 함께 시작됩니다.
   - 실행 시각이 같은 계정은 동시에 실행합니다. 동시에 여는 Chrome 수의 상한은 `동시 실행`으로 정하며 기본값은 4입니다.
4. `■ 전체 중지`를 누르면 새 예약을 멈춥니다.
   - 진행 중인 작업도 즉시 중단하고, 그 계정이 연 Chrome을 닫습니다.
5. 기타 기능

   | 기능 | 설명 |
   | --- | --- |
   | `지금 실행` | 선택한 계정만 바로 1회 실행합니다. 예약과 무관하며 점검용입니다 |
   | `Chrome 창 숨기기` | 체크하면 Chrome을 화면에 띄우지 않고(headless) 실행합니다 |
   | `고급` | Chrome 실행 파일 경로, 시간 제한, 점프 버튼 이름 목록을 바꿉니다 |

**버튼별 결과**는 다음 중 하나로 표시합니다.

| 결과 | 뜻 |
| --- | --- |
| 성공 | 확인 창을 승인했고, 사이트의 실제 성공 신호도 확인함(아래 5장) |

| 확인 창 없음 | 클릭 뒤 확인 창이 뜨지 않음 |
| 실패 | 서버가 요청을 거부함(HTTP 4xx/5xx, 요청 실패), 또는 '횟수 초과' 같은 실패 알림·실패 응답 |
| 확인 불가 | 확인 창은 승인했지만 제한 시간 안에 성공 신호도 실패 신호도 없음. 성공으로 세지 않음 |

## 4. 예약 규칙

### 첫 실행

| 방식 | 동작 |
| --- | --- |
| 즉시 시작 | 전체 시작을 누르는 순간 1회 실행합니다. 이후에는 직전 실행 시작 시각부터 주기마다 실행합니다 |
| 지정 시각에 시작 | 매일 시작 시각을 기준으로 주기 간격의 시각에 실행합니다. 예: 09:00 시작, 30분 주기 → 09:00, 09:30, 10:00 … |

지정 시각 방식에서 첫 실행 시각은 전체 시작을 누른 때에 따라 정해집니다.

- 시작 시각 전에 누르면 시작 시각에 첫 실행을 합니다.
- 이미 지난 뒤에 누르면 지금 이후의 가장 가까운 슬롯에 첫 실행을 합니다. 예: 10:31에 누르면 11:00.

### 종료 시각 (사용자 확정 사항, 선택)

- **비워 두면** `전체 중지`를 누를 때까지 계속 반복합니다. 자정을 넘겨도 같은 간격으로 이어집니다.
- **입력하면** 매일 시작 시각~종료 시각 사이에서만 실행하고, 다음 날 시작 시각에 재개합니다.
  - 종료 시각 정각에 걸리는 슬롯은 실행합니다.
  - 종료 시각이 시작 시각보다 이르면(예: 22:00~02:00) 자정을 넘기는 구간으로 봅니다.
  - 즉시 시작 방식에도 똑같이 적용합니다. 구간 밖에서 전체 시작을 누르면 다음 시작 시각까지 기다립니다.

### 겹침·중복 정책

- 한 계정은 한 번에 한 주기만 실행합니다.
- 한 주기가 길어져 다음 예정 시각을 지나치면 그 예정은 **건너뜁니다**. 로그에 경고를 남기고, 실행이 끝난 뒤 다음 예정 시각을 기다립니다.
- 실행 중에 `지금 실행`을 누르거나 그 계정의 예약 시각이 오면 무시하고 로그에 기록합니다.

### 설정 변경

- 설정 파일(`config.json`)을 직접 고쳐 잘못된 값(예: 반복 주기 `Infinity`, `1e20`, 문자열)이 들어가 있으면, 프로그램을 켤 때 경고 창으로 알립니다. 해당 계정은 비활성으로 바꾸고, 잘못된 항목은 기본값으로 되돌립니다.
- 실행 중에 계산할 수 없는 값이 들어온 계정은 상태가 **설정 오류**로 표시되고 로그에 사유가 남습니다. 다른 계정의 예약은 계속 돕니다.

- 시작 방식, 시각, 주기, 종료 시각을 바꾸면 대기 중인 계정의 다음 실행 시각을 바로 다시 계산해 표에 반영합니다.
- 실행 중인 주기는 그대로 끝까지 진행합니다.

## 5. 한 주기의 동작 (영상 기준)

시연 영상(약 34초)에서 확인한 흐름은 다음과 같습니다.

- 로그인 화면: 아이디·패스워드 입력칸과 `로그인` 버튼
- 로그인 뒤 업소 정보 화면: 점프 컨트롤 4종이 있음
- 각 버튼을 누르면 브라우저 기본 확인 창이 뜸. 예: "albam13.com 내용: … 상단으로 점프할까요?"
- 확인하면 버튼 글자가 `대기 10:02`처럼 바뀜

프로그램은 이 흐름에 맞춰 다음 순서로 동작합니다.

1. 계정마다 새 Chrome 프로세스를 임시 프로필로 띄웁니다. 그래서 계정끼리 쿠키와 로그인 상태가 섞이지 않습니다.
2. 설정 URL로 이동합니다. 비밀번호 입력칸을 찾아 그 앞의 텍스트 칸에 ID를, 비밀번호 칸에 비밀번호를 넣고 `로그인`을 누릅니다.
   - 비밀번호 칸이 사라지면 로그인 성공으로 봅니다.
   - 알림 창이 뜨고 비밀번호 칸이 그대로 남아 있으면 로그인 실패로 봅니다. 사이트 알림 문구를 함께 기록합니다.
3. 로그인 뒤 점프 버튼이 보이지 않으면 설정 URL로 한 번 더 이동합니다.
4. 네 버튼을 순서대로 한 번씩 누르고, 뜨는 확인 창을 승인합니다.
   - 브라우저 기본 확인 창(`confirm`)과 HTML 모달의 `확인` 버튼 둘 다 처리합니다.
   - 버튼이 비활성이거나 글자가 `대기 mm:ss`로 바뀌어 있으면 누르지 않고 **대기/비활성**으로 기록합니다.
   - **확인 창 승인만으로는 성공으로 기록하지 않습니다.** 승인 뒤 사이트의 실제 결과 신호를 기다립니다(기본 8초).

     | 판정 | 신호 |
     | --- | --- |
     | 실패 | 점프 요청이 HTTP 4xx/5xx로 거부됨, 요청 자체가 실패함, 실패 알림 창, JSON 응답의 `ok`/`success`가 `false` |
     | 성공 | 버튼이 대기(`대기 mm:ss`)·비활성으로 바뀜, 카드의 횟수 숫자가 바뀜, 성공 알림 창, JSON 응답의 `ok`/`success`가 `true` |
     | 확인 불가 | 제한 시간 안에 위 신호가 하나도 없음. 성공으로 세지 않음 |

     실패 신호(HTTP 오류 등)를 먼저 봅니다. 화면 신호가 없을 때만 응답 본문을 읽습니다. 점프 뒤 페이지를 새로고침하는 사이트는 새 화면에서 해당 카드가 대기 상태인지로 확인합니다.
5. 결과를 기록하고, 성공·실패·중지 어떤 경우든 `finally` 단계에서 자기 Chrome을 닫습니다.

CAPTCHA나 '자동입력 방지' 같은 추가 인증이 보이면 우회하지 않습니다. 해당 계정을 **실패**로 기록하고 사유를 남깁니다.

## 6. 실패 처리와 시간 제한

`고급` 설정에서 바꿀 수 있습니다.

| 제한 | 기본값 | 넘었을 때 |
| --- | --- | --- |
| 단계 대기(페이지 이동, 로그인 결과, 버튼 찾기) | 20초 | 해당 계정 실패 |
| 확인 창 대기(버튼 클릭 뒤) | 5초 | 그 버튼은 '확인 창 없음' |
| 결과 확인 대기(확인 승인 뒤) | 8초 | 그 버튼은 '확인 불가'(성공으로 세지 않음) |
| 한 주기 전체 | 180초 | 실패 처리 후 Chrome 닫음 |

허용 범위는 단계 1~600초, 확인 창·결과 확인 1~120초, 한 주기 10~3600초입니다. 범위 밖이거나 `inf`·`nan`이면 저장하지 않고 오류를 표시합니다.

계정별 실행은 서로 독립된 작업입니다. 한 계정이 실패하거나 Chrome 실행에 실패하거나 예외가 나도 다른 계정의 예약은 계속 돕니다.

## 7. 보안

- 비밀번호는 Windows DPAPI로 암호화해 `config.json`에 저장합니다. 같은 Windows 사용자 계정에서만 복호화할 수 있습니다.
  - 다른 PC나 다른 사용자로 설정 파일을 옮기면 비밀번호를 다시 입력해야 합니다.
- 비밀번호는 화면(● 표시)과 로그에 평문으로 나오지 않습니다. 로그에는 식별 이름만 남습니다.
- 설정·로그 폴더는 저장소 밖(`%APPDATA%`)에 있으므로 Git에 들어가지 않습니다.

## 8. 모의 사이트로 확인 (실제 계정 불필요)

```bat
run_mock.bat                      :: http://127.0.0.1:8765/owner 에서 실행 (Ctrl+C 종료)
run_mock.bat --cooldown 0         :: 점프 후 대기 없음(주기 반복 확인용)
run_mock.bat --port 8770 --slow 40
```

프로그램의 대상 URL에 `http://127.0.0.1:8765/owner`를 넣고 아래 계정을 등록해 시험합니다. 모두 가짜 계정입니다.

| 아이디 / 비밀번호 | 재현하는 상황 | 기대 결과 |
| --- | --- | --- |
| `test1`/`pass1`, `test2`/`pass2`, `test3`/`pass3` | 정상 | 성공(4개). 다시 실행하면 쿨다운으로 건너뜀 |
| 아무 아이디 + 틀린 비밀번호 | 로그인 실패 알림 | 실패(로그인 실패: …) |
| `cool`/`cool1` | 네 버튼 모두 대기 상태 | 건너뜀 |
| `nobtn`/`nobtn1` | 홍보관 버튼 없음 | 부분 성공(홍보관: 버튼 없음) |
| `nodialog`/`nodialog1` | 매니저 출근부 클릭 시 확인 창 안 뜸 | 부분 성공(확인 창 없음) |
| `limit`/`limit1` | 확인 뒤 '횟수 초과' 알림 | 실패 |
| `modal`/`modal1` | HTML 모달 확인 창 | 성공 |
| `slow`/`slow1` | 응답 지연 `--slow`초. 단계 제한보다 길면 | 실패(시간 초과) |
| `captcha`/`captcha1` | 로그인 뒤 자동입력 방지 화면 | 실패(우회하지 않음) |
| `failjump`/`failjump1` | 확인 승인 뒤 점프 요청이 HTTP 500, 화면·횟수 변화 없음 | 실패(HTTP 500) 4개, 서버 점프 0회 |
| `nosignal`/`nosignal1` | 확인 승인 뒤 서버가 빈 200 응답, 화면 변화 없음 | 확인 불가 4개 → 실패 |
| `quiet`/`quiet1` | 성공 플래그 없는 응답. 버튼 대기 전환·횟수 변화만 있음 | 성공(쿨다운 전환·횟수 변화 확인) |
| `reload`/`reload1` | 점프 뒤 페이지 새로고침 | 성공(새 화면에서 대기 상태 확인) |

모의 서버는 기록 조회와 초기화 기능도 제공합니다.

- `GET http://127.0.0.1:8765/api/stats`: 사용자·점프 종류별 실제 점프 횟수, 세션 ID 앞자리, 로그인 기록. 계정 간 세션이 섞이지 않았는지 이것으로 확인합니다.
- `POST /api/reset`: 기록을 초기화합니다.

Chrome 실행 실패는 `고급 → Chrome 실행 파일`에 실행 파일이 아닌 파일(예: 이 폴더의 `README.md`)을 지정하면 재현할 수 있습니다. 경로 저장 시 파일 존재 여부만 검사하기 때문입니다. 확인 뒤 칸을 비워 원래대로 돌립니다. 자동 테스트에서는 없는 경로를 직접 넣어 확인합니다.

## 10. 실사이트에서 확인하지 못한 점

실제 계정으로 실행해 보지 않았습니다. 아래는 영상만으로 확정할 수 없어 일반적인 방식으로 구현한 부분입니다. 첫 실사용은 `Chrome 창 숨기기`를 끄고 `지금 실행`으로 한 계정씩 점검하기를 권합니다.

- 로그인 입력칸과 버튼의 실제 DOM 구조. 비밀번호 칸과 그 앞의 텍스트 칸, `로그인` 글자로 찾습니다.
- 로그인 뒤 이동 경로. 점프 화면이 아니면 설정 URL로 다시 이동합니다.
- 점프 버튼 글자. 영상의 이름과 정확히 같다고 가정했습니다. 다르면 `고급 → 점프 버튼 이름`에서 고칩니다.
- 확인 뒤 사이트의 성공 신호. 실사이트도 영상처럼 버튼이 `대기 mm:ss`로 바뀐다고 가정했습니다. 신호가 다르면 '확인 불가'로 기록되며 성공으로 세지 않습니다.
- 확인 뒤 사이트가 띄우는 추가 알림 문구. '실패/불가/초과/오류/남은 시간' 등이 있으면 실패로 처리합니다.
- 쿨다운 표시. `대기 mm:ss` 글자 또는 disabled 속성으로 판단합니다.
- 자동화된 Chrome을 사이트가 막는지, 추가 인증을 요구하는지.
